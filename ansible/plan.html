Background

Current State:

Previously stored inventory and configuration files in a clone of the k3s-ansible project. This approach had limitations with version control and distribution of the playbooks.

Goal:

Migrate to using ansible-galaxy to leverage k3s-ansible as a dependency. This allows:

  • Push inventory and cluster configuration to local Gitea
  • Maintain separation of concerns (playbook code vs cluster config)
  • Easier updates to k3s-ansible without manual merges
  • Better version management and reproducibility

Technology Stack:

  • Ansible Galaxy - package management
  • k3s-ansible - upstream playbook
  • Local Gitea instance - internal repository
  • K3s - lightweight Kubernetes distribution

Planning

Implementation Steps:

  • Create requirements.yml to pin k3s-ansible to a specific version
  • Use existing k3s-ansible playbooks directly (no wrapper needed)
  • Reorganize to override vars via group_vars/ and host_vars/
  • Include vault-globals.yml in the vars hierarchy
  • Configure ansible.cfg for proper playbook discovery
  • Test with ansible-galaxy install -r requirements.yml
  • Push vault-globals.yml and inventory.yml to local Gitea (committed)
  • Create README.md documenting manual playbook invocation and vault password handling
  • Document deployment workflow: ansible-playbook k3s.orchestration.site -i inventory.yml

File Structure Goal:

  • requirements.yml - Pin k3s-ansible version
  • inventory.yml - Cluster node definitions (committed to Gitea)
  • vault-globals.yml - Encrypted secrets k3s_token (committed to Gitea)
  • group_vars/ - Variable overrides for k3s_cluster group
  • host_vars/ - Host-specific overrides (if needed)
  • ansible.cfg - Configure for galaxy-installed roles
  • README.md - Deployment instructions and vault password usage

Deployment Command:

After running ansible-galaxy install -r requirements.yml, deploy using:

ansible-playbook k3s.orchestration.site -i inventory.yml --ask-vault-pass

This invokes the upstream k3s-ansible playbook directly with your local inventory and encrypted variables.

Requirements.yml Example:

---
collections:
  - name: community.general

roles:
  - src: https://github.com/k3s-io/k3s-ansible
    version: v2.13.0  # pin to specific version
    name: k3s
